# План запуска Supplier Radar

Цель: поднять публичное демо на РФ-инфраструктуре и отправить результат HR в Goulash.tech.

**Статус:**
- [x] Репозиторий: https://github.com/Riper21/GoulashRadar (v0.1.0)
- [ ] Демо-URL
- [ ] Сообщение HR

**Критерии успеха запуска:**
1. Демо-URL отвечает, `GET /api/health` → `{"status":"ok"}`
2. Первый поиск «мука, Москва» → карточки ≤ 60 с; повторный → ≤ 3 с (cache-replay)
3. Хром-виджет работает против прод-URL (обе цветовые схемы)
4. RU-only: в выдаче нет иностранных доменов при включённой галке
5. Сообщение HR отправлено, репо доступно по ссылке

---

## Фаза A. Деплой (1–2 ч) — из репо GitHub

### Вариант A — Timeweb Cloud Apps (рекомендуемый)
1. Аккаунт → «Apps» → создать приложение → **GitHub → Riper21/GoulashRadar**
   (платформа сама подтянет `Dockerfile` и соберёт образ; подключить аккаунт GitHub при создании)
2. Порт контейнера: **8000** (healthcheck уже в Dockerfile)
3. **Обязательно**: подключить volume → `/app/data` и задать env
   `SR_DB_PATH=/app/data/supplier_radar.db` — иначе SQLite теряется при ре-деплое
   (вместе с кэшем SERP/страниц и «мгновенным» повторным демо)
4. Env: `SR_PORT=8000`; `LLM_API_KEY` (ai.dreamn-api-market.ru) — опционально,
   движки: `SR_YANDEX=0`, `SR_TWOGIS=0` (дефолты)
5. Домен: выданный платформой поддомен `*.twc1.net` (решено: достаточно)
6. После сборки: убедиться, что контейнер healthy

### Вариант B — VPS (Selectel / Timeweb / reg.ru, ~300–500 ₽/мес)
```bash
ssh root@<vps>
git clone https://github.com/Riper21/GoulashRadar && cd GoulashRadar
cp .env.example .env && nano .env       # LLM_API_KEY при желании
docker-compose up -d                    # :8000
# опционально Caddy для авто-HTTPS:
# echo "radar.<домен> { reverse_proxy 127.0.0.1:8000 }" > /etc/caddy/Caddyfile
```
Volume `radar-data` уже в docker-compose.yml.

### Вариант C — Yandex Cloud
Serverless Containers не подходит (эфемерное хранилище), Compute Cloud VPS → как B.

> Ключевой нюанс: **персистентность SQLite**. Кэш = страховка демо от «движки легли».

## Фаза B. Прогрев и верификация прода (30 мин)

- [ ] `GET /api/health` — ok + состояния движков
- [ ] Прогрев демо-запросов (сериально, ~5 мин):
  `мука/Москва`, `упаковка для кофе/СПб`, `сыры/Казань`, `кофе/Москва`, `специи/Екатеринбург`
  (POST /api/search → дождаться done) — после прогрева демо стабильно при любом раскладе
- [ ] Smoke:
  - [ ] новый запрос ≤ 60 с, карточки с телефонами
  - [ ] повторный той же пары ≤ 3 с, stats `cache_replay:true`
  - [ ] SSE живой: `curl -N <demo>/api/jobs/<id>/events`
  - [ ] CORS: запрос с `Origin: chrome-extension://…` → `ACAO: *`
  - [ ] `ru_only:false` возвращает иностранные домены
  - [ ] CSV-экспорт скачивается
- [ ] Виджет: Load unpacked → в настройках прод-URL → поиск → обе темы

## Фаза C. Материалы и отправка (1 ч)

- [ ] Видео 60–90 с: форма → конвейер → карточки по SSE → скоринг → сравнение → CSV
- [ ] Скриншоты: выдача, карточка, сравнение, виджет в 2 темах
- [ ] `zip -r supplier-radar-extension.zip extension/` — приложить к письму
- [ ] `HR_MESSAGE.md`: вставить ссылки на репо и демо
- [ ] Отправка; первые 3 дня — daily-чек `/api/health`

## Риски и план Б

| Риск | Вероятность | Митигация |
|---|---|---|
| DDG банит IP хостинга | средняя | breaker + cache-first; **прогрев гарантирует демо при полном бане** |
| LLM-прокси медленный/5xx (замечено: 50–90 с на длинных промптах, были 502) | высокая | LLM опционален в демо; текст сжимается до 2K; ретрай на 5xx; каскад работает на эвристиках |
| Платформа без volume | низкая | VPS (вариант B) |
| SQLite под нагрузкой | низкая (прототип) | README честно фиксирует; прод-путь Postgres |
| Демо лежит при просмотре HR | низкая | видео-фоллбэк в письме |
