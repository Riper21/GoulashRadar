Отправляю результат по тестовому заданию — сервис Supplier Radar.

**Ссылки:**
- Репозиторий: [github.com/…/supplier-radar](https://github.com/...) — README с decision log, тесты, docker-compose
- Демо: [demo-link] — попробовать: категория «мука», город «Москва» (первый поиск ~30 с, повторный — из кэша за 2 с)

**Как это работает (коротко):**
Сервис в реальном времени опрашивает поисковые движки (DuckDuckGo HTML, без капчи),
отбирает релевантные сайты, обходит их (robots.txt, бережный pacing), извлекает
структурированные карточки поставщиков каскадом: адаптеры B2B-каталогов → JSON-LD →
эвристики → LLM (только при низкой полноте, с бюджетом и обязательными evidence-цитатами,
галлюцинации отсекаются валидатором). Дубли склеиваются (ИНН → телефон → домен),
каждая карточка получает прозрачный рейтинг с разбором «почему», есть сравнение
бок о бок, заметки и экспорт CSV. В карточке всегда ссылка на первоисточник.

**Ключевые решения:**
- Живой парсинг вместо датасета — конвейер доказывает end-to-end работу на любом запросе
- Кэш трёхуровневый (SERP 48 ч, страницы 7 д, выдача 6 ч) — стабильное демо не зависит от здоровья движков
- LLM — парсер, а не источник фактов: только цитаты, проверяемые детерминированным валидатором (чексумма ИНН, E.164)
- Честные ограничения: JS-only сайты и Yandex-капча задокументированы, продакшен-путь — через официальные API (2GIS-драйвер готов)

С удовольствием расскажу подробнее на собеседовании — особенно про границы доверия LLM
и метрики качества извлечения.
